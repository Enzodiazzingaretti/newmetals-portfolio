# New Metals — Portfolio

**Site for a metalwork studio**: services, selected work with technical detail sheets, process and values — plus an admin panel the studio uses to publish new jobs without calling a developer.

🔗 **[newmetals-portfolio.vercel.app](https://newmetals-portfolio.vercel.app)**

---

## What it does

- **Work gallery** where each piece opens into a modal with photos and a technical sheet
- **Canvas spark animation** in the hero — welding sparks, drawn rather than filmed, so it costs a few kilobytes instead of a video
- **Admin panel** at `/admin` for editing brand, services, work, photos and process
- **Reorderable lists** in the panel, so the studio controls what leads the page

## Accessibility

The modals are the part most sites get wrong, so they got a hand-rolled **`useFocusTrap`** hook: focus enters the modal, cycles inside it, and returns to the trigger on close. Keyboard and screen-reader users get the same experience as everyone else, which for a modal is the whole test.

## Git-backed content

No database. The editable source of truth is `public/content.json`; the panel reads it and rewrites it **back into this repository through the GitHub API**, which triggers a Vercel redeploy — the site is live with the change in about a minute.

Images uploaded from the panel are **compressed to WebP in the browser** before they ever reach the server, and land in `public/assets/uploads/`.

Every content change is therefore a commit: full history, and `git revert` undoes a bad edit.

## Security

- Password hashed with **`scrypt`**, never stored in plaintext
- Signed session cookie, 12-hour expiry
- **Write allowlist** — the API refuses any path outside `public/content.json` and the uploads directory
- The target repository is **never hardcoded**; it defaults to the deployment's own `VERCEL_GIT_REPO_*`, so a clone can't write into the original

## Running locally

```bash
npm install

```

## Admin setup

Three environment variables in Vercel — see **[`ADMIN_SETUP.md`](ADMIN_SETUP.md)** for the full walkthrough:

| Variable | Purpose |
|---|---|
| `ADMIN_PASSWORD_HASH` | Generated by the setup script |
| `SESSION_SECRET` | Signs the session cookie |
| `GITHUB_TOKEN` | Write access to this repository |

Without them, `/admin` shows the login but reports itself as unconfigured.

## Contenido sobre git

Sin base de datos. La fuente de verdad editable es `public/content.json`; el panel lo lee y lo reescribe **de vuelta en este repositorio a través de la API de GitHub**, lo que dispara un redeploy de Vercel — el sitio queda actualizado en aproximadamente un minuto.

Las imágenes que se suben desde el panel **se comprimen a WebP en el navegador** antes de llegar al servidor, y se guardan en `public/assets/uploads/`.

Cada cambio de contenido es entonces un commit: historial completo, y `git revert` deshace una edición equivocada.
